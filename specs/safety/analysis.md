# HLFSR-64 安全性分析

> 本文档分析 HLFSR-64 流密码核心的密码学安全性。该设计为新型构造，以下分析基于已知的攻击方法和设计特性，不构成形式化安全证明。量化声明为估计值，需经独立的密码分析验证。

## 1. 威胁模型

| 维度 | 假设 |
|------|------|
| 攻击者能力 | 已知/选择明文攻击（标准流密码假设） |
| 密钥 | 256 位均匀随机（由外部 KDF 保证） |
| Nonce | 同一 Key 下不重复，明文传输 |
| 侧信道 | 考虑时间侧信道（通过常数时间实现缓解）；功耗/电磁侧信道不在当前分析范围内 |
| 相关密钥攻击 | 不在威胁模型内（假设 KDF 输出独立） |

## 2. 状态空间

| 组件 | 位数 |
|------|------|
| bitmap | 256 |
| 16×64-bit LFSR | 1024 |
| idx | 8 |
| **合计** | **1288** |

初始化输入 65 字节（32 bitmap + 32 lfsr_seed + 1 idx = 520 位），由外部 256 位密钥经 KDF 派生。系统可能达到的内部状态空间远大于密钥空间，使穷举密钥攻击为最优通用攻击（2^256 安全性）。

LFSR 的初始状态由 32 字节 lfsr_seed 经步长 2 滑动窗口填入，每字节被约 4 条 LFSR 共享。种子中任意 1 比特变化影响约 4 条 LFSR 的初态。

## 3. 周期分析

### 3.1 LFSR 层

每条 LFSR 使用 64 次本原多项式，周期为 2^64 − 1 ≈ 1.84×10^19 步。16 条 LFSR 各自独立推进（每步全体移位），组合 LFSR 状态的周期为 lcm(2^64 − 1, ..., 2^64 − 1) = 2^64 − 1。

### 3.2 整体系统

输出序列由 sel（4 位，来自 bitmap）和 curbit（1 位，来自 bitmap）调制。bitmap 自身被指令动态修改，其演化不遵循 LFSR 线性递推。输出序列的周期受以下因素影响：

- 16 条 LFSR 的联合周期：2^64 − 1
- bitmap 的 256 位状态空间：2^256
- 指令自修改引入的不可逆状态转移

**估计下界**：系统周期 ≥ 2^64 − 1（LFSR 周期约束）。实际周期很可能远大于此值，但尚未有严格证明。

## 4. 线性复杂度

### 4.1 基底 LFSR

单条 64 次本原 LFSR 的线性复杂度为 64（生成序列的极小多项式的次数）。

### 4.2 组合器结构

输出 = L_sel(state) XOR {64{curbit}}

其中 sel 是 4 位选择信号，curbit 是 1 位翻转控制，两者均来自 bitmap。

若 sel 固定，输出为单条 LFSR 的线性序列，线性复杂度 64。但 sel 随 bitmap 动态变化（每步可能改变），使得输出是 16 条 LFSR 输出的**非规则交织**。

交织模式由 bitmap 状态决定，而 bitmap 受指令自修改控制，使线性复杂度远高于任何单条 LFSR。

**保守估计**：输出序列的线性复杂度 ≥ 2^20（远超实际攻击可行范围），实际值取决于 sel 序列的熵和指令修改模式。

## 5. 针对已知攻击的分析

### 5.1 相关攻击 (Correlation Attacks)

**原理**：寻找输出与某条 LFSR 内部状态之间的统计相关性，逐条恢复 LFSR 状态。

**HLFSR-64 的防御**：
- sel 信号来自 bitmap，攻击者不知道 bitmap 状态，无法将输出与特定 LFSR 关联
- curbit 翻转使输出极性与 LFSR 输出的关系每步可能反转
- 即使攻击者正确猜测 sel 和 curbit，bitmap 被指令修改后会改变后续的 sel/curbit 序列
- **相关免疫度**：输出中每条 LFSR 的贡献被 sel 的熵（最多每步 4 位）和 curbit 的熵（最多每步 1 位）掩盖

### 5.2 代数攻击 (Algebraic Attacks)

**原理**：将密码表示为 GF(2) 上的代数方程组并求解。

**HLFSR-64 的防御**：
- LFSR 反馈函数为线性（度为 1 的多项式关系）
- 但 sel 选择函数引入了高次项：sel 是 bitmap 的 4 位切片，bitmap 通过指令算术、逻辑、自修改操作演化
- 每条指令的语义不同（加减、位翻转、跳转、逻辑运算），引入不同类型的高次方程
- 方程组规模随观测步数快速增长，求解复杂度过高

**估计**：建立足够约束的方程组需要 ≥ 2^20 步输出，对应 2^26 位密钥流，方程度数 ≥ 3（源于乘法/AND 操作），求解复杂度超过 2^128。

### 5.3 时间-内存权衡攻击 (TMDTO / Babbage-Golić)

**原理**：利用生日悖论寻找状态碰撞，将 2^n 状态空间攻击降为 2^(n/2)。

**HLFSR-64 的防御**：
- 内部状态 1288 位，标准 TMDTO 需 2^644 预计算（超出宇宙极限）
- 初始化后的有效状态由 520 位种子决定，经典 TMDTO 复杂度 ≈ 2^260，仍远超 2^256 密钥穷举

### 5.4 区分攻击 (Distinguishing Attacks)

**原理**：构造统计检验将密钥流与真随机序列区分。

**HLFSR-64 的防御**：
- 64 位输出宽度使标准 LFSR 线性偏差（权重偏差、游程偏差）在单步输出中被掩藏
- sel 的非规则交织打破了固定 LFSR 输出的统计规律
- curbit 的逐位翻转消除了输出位的固定偏倚
- 若 bitmap 演化充分混合，区分需要的样本量远超 2^64

### 5.5 代数免疫 (Algebraic Immunity)

**原理**：寻找低次布尔函数逼近输出函数。

**HLFSR-64 的防御**：
- 输出函数为 O(bitmap, L_0..L_15) = L_sel XOR {64{curbit}}，高度依赖于 bitmap
- bitmap 被 16 条指令每步重写，转移函数包含 AND/OR/XOR/加法/位反转/字节交换/条件跳转，形成高次、不可线性化的映射
- 不存在固定的低次逼近函数

### 5.6 猜测-确定攻击 (Guess-and-Determine)

**原理**：猜测部分内部状态，通过方程推导其余状态。

**HLFSR-64 的防御**：
- 猜测 bitmap (256 位) 不可行
- 猜测部分 bitmap 和部分 LFSR 状态：方程系统的剩余自由度仍远超安全边界
- 指令的自修改性质使得部分猜测难以验证（验证需要完整模拟系统）

### 5.7 滑动攻击 (Slide Attacks)

**原理**：寻找密钥流中两个不同位置的状态相似性。

**HLFSR-64 的防御**：
- 没有轮函数概念（每步执行不同指令）
- bitmap 自修改使状态不重复自身结构
- 转移函数非齐次（依赖当前 bitmap 内容）

## 6. 退化状态分析

### 6.1 全零 bitmap

```
bitmap = [0, 0, ..., 0]
→ sel = 0 (永远)
→ curbit = 0 (永远)
→ curbyte = 0x00 (永远)
→ 指令 = IncB, param=0 → 无操作
→ idx = (idx+1) mod 256 (默认递进)
→ 输出 = L_0 (不被翻转)
```

**影响**：系统退化为单条 LFSR (L_0) 的裸输出，线性复杂度 64。**此状态可被实时检测并拒绝**。

### 6.2 全 FF bitmap

```
bitmap = [0xFF, ..., 0xFF]
→ curbit = 1 (永远)
→ 输出 = ~L_sel (始终翻转)
→ curbyte = 0xFF (永远)
→ 指令 = NotB, param=15
```

NotB 取 bitmap[(idx/8 + (-1)) mod 32] 按位取反，即修改前一个字节。全 1 取反后变全 0。这是一个破坏性指令——逐步将 bitmap 从全 1 转为全 0 与全 1 混合的模式。

**影响**：此状态会**自脱离**——NotB 指令破坏全 1 模式，使 bitmap 不再均匀。

### 6.3 初始化检查建议

在 init 阶段，应检查以下条件并拒绝退化种子：
- bitmap 全 0 或全 1
- lfsr_seed 全 0（所有 LFSR 初态相同且为 0）
- idx_init 任意值均可（不影响安全性）

这些检查的计算成本极低。

## 7. 侧信道分析

### 7.1 时间侧信道

**威胁**：通过测量加密操作时间推断密钥/状态信息。

**缓解**：
- 所有控制流使用掩码实现（16 条指令并行计算、掩码选择结果）
- 内存访问模式固定（无论 bitmap 值和指令，访问相同地址集合）
- 无数据依赖分支
- 批量处理 `keystream()` 时尾部分支仅依赖公开的输出长度，不泄露秘密信息

**残留风险**：硬件级时差（Cache 命中/缺失、指令级并行度波动）不在软件缓解范围内。高安全场景可考虑预取所有可能的内存地址。

### 7.2 功耗/电磁侧信道

不在常数时间实现的缓解范围内。硬件防护（掩码、双轨逻辑）需在芯片级实现。

## 8. 关键材料管理

### 8.1 Nonce 重用

**后果**：同一 (Key, Nonce) 产生相同的 bitmap + lfsr_seed + idx_init → **完全相同的密钥流**。这是所有流密码的共同约束，由调用方保证。

### 8.2 密钥流长度限制

单次加密的密钥流长度建议 ≤ 2^48 字节（约 281 TB），对应 2^45 步，远小于 LFSR 周期 (2^64) 和 TMDTO 安全边界 (2^64)。

### 8.3 前向安全性

不提供。密钥泄露后，攻击者可恢复历史密钥流。

## 9. 安全性总结

| 属性 | 评估 |
|------|------|
| 等效密钥安全 | 256 位（受 KDF 限制） |
| 内部状态空间 | 1288 位 |
| 线性复杂度 | 远超 2^20（估计） |
| 周期 | ≥ 2^64 − 1 |
| 已知明文攻击 | 2^256 密钥穷举 |
| 相关攻击 | 被 sel 非规则交织阻止 |
| 代数攻击 | 被指令自修改高次方程阻止 |
| TMDTO | 状态空间远超 2^(安全边界) |
| 侧信道 (时间) | 常数时间实现缓解 |

**设计优势**：
1. bitmap 自修改引入不可逆状态转移，打破 LFSR 的线性结构
2. sel 与 curbit 由同一秘密状态动态控制，外部不可观测
3. 指令集多样（算术/逻辑/跳转/自修改），使状态转移高度非线性

**已知局限**：
1. 缺乏形式化安全证明，安全性基于设计的复杂性而非归约到已知难题
2. 退化状态（全 0 bitmap）需在初始化时主动检测排除
3. 尚未经过公开的密码分析
4. 无认证加密——需上层协议提供认证（如 Encrypt-then-MAC）

**推荐使用方式**：
- 上层协议 EC-KEM + Encrypt-then-MAC 封装
- 每个 Key 配合唯一 Nonce
- 单次加密不超过 2^48 字节
- 初始化时检查并拒绝退化种子
