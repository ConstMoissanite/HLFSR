# HLFSR-64 安全性分析

> 本文档分析 HLFSR-64 流密码核心的密码学安全性。该设计为新型构造，以下分析基于已知的攻击方法和设计特性，不构成形式化安全证明。量化声明为估计值，需经独立的密码分析验证。

## 1. 威胁模型

| 维度 | 假设 |
|------|------|
| 攻击者能力 | 已知/选择明文攻击（标准流密码假设） |
| 密钥 | 256 位均匀随机（由外部 KDF 保证） |
| Nonce | 同一 Key 下不重复，明文传输 |
| 侧信道 | 考虑时间侧信道（通过常数时间实现缓解）；功耗/电磁侧信道不在当前分析范围内 |
| 相关密钥攻击 | 不在威胁模型内（假设 KDF 输出独立） |

## 2. 状态空间

| 组件 | 位数 |
|------|------|
| bitmap | 256 |
| 16×64-bit LFSR | 1024 |
| idx | 8 |
| **合计** | **1288** |

初始化输入 65 字节（32 bitmap + 32 lfsr_seed + 1 idx = 520 位），由外部 256 位密钥经 KDF 派生。系统可能达到的内部状态空间远大于密钥空间，使穷举密钥攻击为最优通用攻击（2^256 安全性）。

LFSR 的初始状态由 32 字节 lfsr_seed 经步长 2 滑动窗口填入，每字节被约 4 条 LFSR 共享。种子中任意 1 比特变化影响约 4 条 LFSR 的初态。

## 3. 周期分析

### 3.1 LFSR 层

每条 LFSR 使用 64 次本原多项式，周期为 2^64 − 1 ≈ 1.84×10^19 步。16 条 LFSR 各自独立推进（每步全体移位），组合 LFSR 状态的周期为 lcm(2^64 − 1, ..., 2^64 − 1) = 2^64 − 1。

### 3.2 整体系统

输出序列由两个 4 位选择信号 sel0、sel1（来自同一字节 idx 和 idx−4 位置）和 curbit（1 位，来自 bitmap）调制。16 条 LFSR 全体推进，双路选通异或后经 64×64 黄金比常数乘性混合，再与 {64{curbit}} 异或。

强制回填机制保证所有 16 条指令均修改 bitmap：步进/跳转指令额外将输出低 8 位异或进目标字节。bitmap 每步必然被修改，消除冻结风险。

系统周期受以下因素影响：
- 16 条 LFSR 的联合周期：2^64 − 1
- bitmap 的 256 位状态空间：2^256
- 指令自修改 + 强制回填引入的不可逆状态转移
- 乘性混合（乘以奇数 = GF(2^64) 上的双射）不引入额外周期约束

**估计下界**：系统周期 ≥ 2^64 − 1。实际周期受 bitmap 演化驱动，远大于 LFSR 周期。

## 4. 线性复杂度

### 4.1 基底 LFSR

单条 64 次本原 LFSR 的线性复杂度为 64。

### 4.2 DM 组合器结构

```
raw  = L_sel0 ^ L_sel1                      // 双路异或（线性）
mix  = raw × 0x9E3779B97F4A7C15             // 64×64 模乘（非线性，进位链）
output = mix ^ {64{curbit}}                 // curbit 翻转（线性）
```

关键在乘性混合：GF(2^64) 上的模乘（奇数乘→双射）在 GF(2) 上是高度非线性的——每个输出位经进位链依赖多个输入位。即使 raw = 0（sel0 == sel1 时，约占 1/16），乘性混合输出也为 0，但 curbit 翻转层将其变为 0 或 all-1，掩盖了零块模式。

sel0 和 sel1 来自同一 curbyte 偏移 4 位的两个 4 位窗口。当 bit_pos < 4 时 sel1 为零填充，但 sel0 仍然完整。两个选择器重叠但不独立，这引入了额外的交织熵。

**估计**：DM 组合器的等效线性复杂度远超 2^64。乘性混合打破了 Fibonacci LFSR 的线性递推在字内位关联上的体现（Golomb G3 自相关 0/32 PASS 确认了这一点）。

## 5. 针对已知攻击的分析

### 5.1 相关攻击 (Correlation Attacks)

**原理**：寻找输出与某条 LFSR 内部状态之间的统计相关性，逐条恢复 LFSR 状态。

**HLFSR-64 DM 的防御**：
- 双路选通 (sel0 + sel1) 使输出依赖于两条 LFSR 的异或，攻击者需同时猜测两个选择器
- 64×64 乘性混合是非线性映射（进位链），输出位与 LFSR 状态位之间无简单线性关系
- curbit 翻转使输出极性与 LFSR 输出的关系每步可能反转
- bitmap 被所有 16 条指令每步修改（含强制回填），sel/curbit 序列持续变化
- Golomb G3 自相关 0/32 PASS（等同 ChaCha20），确认无位间可检测统计相关

### 5.2 代数攻击 (Algebraic Attacks)

**原理**：将密码表示为 GF(2) 上的代数方程组并求解。

**HLFSR-64 的防御**：
- LFSR 反馈函数为线性（度为 1 的多项式关系）
- 但 sel 选择函数引入了高次项：sel 是 bitmap 的 4 位切片，bitmap 通过指令算术、逻辑、自修改操作演化
- 每条指令的语义不同（加减、位翻转、跳转、逻辑运算），引入不同类型的高次方程
- 方程组规模随观测步数快速增长，求解复杂度过高

**估计**：建立足够约束的方程组需要 ≥ 2^20 步输出，对应 2^26 位密钥流，方程度数 ≥ 3（源于乘法/AND 操作），求解复杂度超过 2^128。

### 5.3 时间-内存权衡攻击 (TMDTO / Babbage-Golić)

**原理**：利用生日悖论寻找状态碰撞，将 2^n 状态空间攻击降为 2^(n/2)。

**HLFSR-64 的防御**：
- 内部状态 1288 位，标准 TMDTO 需 2^644 预计算（超出宇宙极限）
- 初始化后的有效状态由 520 位种子决定，经典 TMDTO 复杂度 ≈ 2^260，仍远超 2^256 密钥穷举

### 5.4 区分攻击 (Distinguishing Attacks)

**原理**：构造统计检验将密钥流与真随机序列区分。

**Golomb 三公设实测**（16 MiB 样本，ChaCha20 同机基线参考）：

| 检验 | HLFSR-64 DM | ChaCha20 (OpenSSL) | 结论 |
|------|-------------|---------------------|------|
| G1 频率 | 50.000% ± 0.005% PASS | 50.004% PASS | 等同 |
| G2 游程 χ² | ~2080 FAIL | ~2070 FAIL | 等同（大样本固有问题） |
| G3 自相关 | 0/32 PASS | 0/32 PASS | 等同 |

G2 "FAIL" 是统计检验框架在大样本（6700 万游程）下的固有问题——ChaCha20 同样"FAIL"且 χ² 值接近。G3 是关键鉴别指标：原始单路 HLFSR 19/32 FAIL，DM 版 0/32 PASS，证实乘性混合成功消除了 Fibonacci LFSR 的字内自相关。

**HLFSR-64 DM 的防御**：
- 64×64 乘性混合通过进位链将每个输出位变为多个 LFSR 状态位的非线性函数
- 双路选通 + 强制回填消除了 bitmap 冻结风险，确保系统状态充分演化
- 16 MiB 样本下无法区分于 ChaCha20 基线

### 5.5 代数免疫 (Algebraic Immunity)

**原理**：寻找低次布尔函数逼近输出函数。

**HLFSR-64 DM 的防御**：
- 输出函数为 O(bitmap, L_0..L_15) = ((L_sel0 ^ L_sel1) × K) ^ {64{curbit}}
- 64×64 模乘（K 为奇数）在 GF(2) 上的代数次数约为 32（进位移位链的半长）。将 LFSR 的线性状态映射到输出的布尔函数天然为高次
- bitmap 被所有 16 条指令每步修改，转移函数包含 AND/OR/XOR/加法/位反转/字节交换/条件跳转 + 强制回填
- 不存在固定低次布尔函数可有效逼近输出函数

### 5.6 猜测-确定攻击 (Guess-and-Determine)

**原理**：猜测部分内部状态，通过方程推导其余状态。

**HLFSR-64 的防御**：
- 猜测 bitmap (256 位) 不可行
- 猜测部分 bitmap 和部分 LFSR 状态：方程系统的剩余自由度仍远超安全边界
- 指令的自修改性质使得部分猜测难以验证（验证需要完整模拟系统）

### 5.7 滑动攻击 (Slide Attacks)

**原理**：寻找密钥流中两个不同位置的状态相似性。

**HLFSR-64 的防御**：
- 没有轮函数概念（每步执行不同指令）
- bitmap 自修改使状态不重复自身结构
- 转移函数非齐次（依赖当前 bitmap 内容）

## 6. 退化状态分析

### 6.1 全零 bitmap

```
bitmap = [0, 0, ..., 0]
→ sel0 = 0, sel1 = 0 (永远)
→ curbit = 0 (永远)
→ curbyte = 0x00 (永远)
→ 指令 = IncB, param=0
```

DM 下：sel0 == sel1 == 0，raw = L_0 ^ L_0 = 0，乘性混合后 raw = 0，output = 0。强制回填将 output[7:0] = 0 异或进 target，bitmap 不变（0 ^ 0 = 0）。

**影响**：输出为全零。此状态**可被实时检测并拒绝**——调用方在 init 时检查 bitmap 是否为全零。

### 6.2 全 FF bitmap

```
bitmap = [0xFF, ..., 0xFF]
→ curbit = 1 (永远)
→ curbyte = 0xFF (永远)
→ 指令 = NotB, param=15
```

NotB 将 bitmap[(idx/8 − 1) mod 32] 按位取反（全 1→全 0）。强制回填生效：步进/跳转指令时额外异或 output 低 8 位，加速 bitmap 模式破坏。

**影响**：此状态**自脱离**——NotB 破坏全 1 字节，强制回填加速混合。

### 6.3 强制回填的影响

DM 设计中所有 16 条指令均修改 bitmap（步进/跳转 6 条指令额外异或 output[7:0] 进目标字节）。这意味着：
- 不存在"不修改 bitmap"的纯控制流步骤
- 即使 curbyte 连续落在步进/跳转指令区间，bitmap 持续被扰动
- 退化状态在少数步骤内就会被破坏

### 6.4 初始化检查建议

在 init 阶段检查并拒绝：
- bitmap 全 0 或全 1
- lfsr_seed 全 0（所有 LFSR 初态为零）

这些检查计算成本极低。

## 7. 侧信道分析

### 7.1 时间侧信道

**威胁**：通过测量加密操作时间推断密钥/状态信息。

**缓解**：
- 所有控制流使用掩码实现（16 条指令并行计算、掩码选择结果）
- 内存访问模式固定（无论 bitmap 值和指令，访问相同地址集合）
- 无数据依赖分支
- 批量处理 `keystream()` 时尾部分支仅依赖公开的输出长度，不泄露秘密信息

**残留风险**：硬件级时差（Cache 命中/缺失、指令级并行度波动）不在软件缓解范围内。高安全场景可考虑预取所有可能的内存地址。

### 7.2 功耗/电磁侧信道

不在常数时间实现的缓解范围内。硬件防护（掩码、双轨逻辑）需在芯片级实现。

## 8. 关键材料管理

### 8.1 Nonce 重用

**后果**：同一 (Key, Nonce) 产生相同的 bitmap + lfsr_seed + idx_init → **完全相同的密钥流**。这是所有流密码的共同约束，由调用方保证。

### 8.2 密钥流长度限制

单次加密的密钥流长度建议 ≤ 2^48 字节（约 281 TB），对应 2^45 步，远小于 LFSR 周期 (2^64) 和 TMDTO 安全边界 (2^64)。

### 8.3 前向安全性

不提供。密钥泄露后，攻击者可恢复历史密钥流。

## 9. 安全性总结

| 属性 | 评估 |
|------|------|
| 等效密钥安全 | 256 位（受 KDF 限制） |
| 内部状态空间 | 1288 位 |
| 线性复杂度 | 远超 2^64（乘性混合 + 双路选通） |
| 周期 | ≥ 2^64 − 1 |
| 已知明文攻击 | 2^256 密钥穷举 |
| 相关攻击 | 双路选通 + 乘性混合打破字内相关 (G3 0/32 PASS) |
| 代数攻击 | 16 条指令自修改 + 64×64 非线性乘 + 强制回填 |
| 区分攻击 | 16 MiB 样本与 ChaCha20 无法区分 |
| TMDTO | 状态空间 1288 位，远超 2^256 |
| 侧信道 (时间) | 常数时间实现缓解 |

**DM 设计优势**：
1. 64×64 乘性混合（进位链非线性）打破 Fibonacci LFSR 字内自相关
2. 双路选通 (sel0 + sel1) 增加输出复杂度，消除零输出退化
3. 强制回填保证每步修改 bitmap，消除冻结风险
4. 所有 16 条指令每步执行，bitmap 演化不可逆
5. Golomb G3 0/32 PASS，与 ChaCha20 基线等效

**已知局限**：
1. 缺乏形式化安全证明
2. 退化状态（全 0 bitmap）需 init 时检测排除
3. 尚未经过公开的独立密码分析
4. 无认证加密——需上层协议提供

**推荐使用方式**：
- 上层协议 EC-KEM + Encrypt-then-MAC
- 每个 Key 配合唯一 Nonce
- 单次加密不超过 2^48 字节
- init 时检查并拒绝退化种子
