# HLFSR-64 MF 安全性分析

## 1. 威胁模型

| 维度 | 假设 |
|------|------|
| 攻击者能力 | 已知/选择明文（标准流密码） |
| 密钥 | 256 位均匀随机（外部 KDF 保证） |
| Nonce | 同一 Key 下不重复 |
| 侧信道 | 时间侧信道（常数时间缓解） |
| 相关密钥 | 不在模型内（KDF 输出独立） |

## 2. 状态空间

| 组件 | 位数 | 结构 |
|------|------|------|
| matrix | 256 | 16×16 位 |
| 16×64-bit LFSR | 1024 | Fibonacci, 本原多项式 |
| idx | 8 | 0–255，行/列分解 |
| **合计** | **1288** | |

初始化输入 65 字节（32 matrix + 32 lfsr_seed + 1 idx = 520 位），密钥空间 256 位（外部 KDF 约束）。内部状态 1288 位远超密钥空间，穷举密钥为最优通用攻击（2^256）。

## 3. 代数结构分析

### 3.1 状态转移函数

每步操作可写为：

```
row_t     = idx_t >> 4
curword_t = matrix_t[row_t]                             // (1) 16 位读取
(p, s0, s1, s2) = decode(curword_t)                    // (2) 解码
raw_t = (L_s0 ^ L_s1 ^ L_s2) × K                       // (3) 三路 XOR + 乘性混合
output_t = raw_t ^ {64{curbit}}                         // (4) 输出
matrix_{t+1}[row_t] = ROL16(matrix_t[row_t] ^ raw_t[15:0], p)  // (5) 回填 + 移位
idx_{t+1} = idx_t + 1                                   // (6) 指针推进
```

### 3.2 转移函数的非线性源

1. **64×64 模乘 (×K)**：K = 0x9E3779B97F4A7C15（奇数→双射）。在 GF(2) 上，乘法进位链产生约 32 次代数度。LFSR 输出为线性（度 1），经乘法后输出函数度 ≈ 32。

2. **指令字依赖**：p, s0, s1, s2 由 matrix[row] 决定，而 matrix[row] 又由上一步的 raw 和自身决定。这是**闭环反馈**——选通信号来自被选通信号修改的状态。

3. **行移位**：ROL16 by p（p 自身来自 matrix）引入数据依赖的位重排，打破固定的位位置对应关系。

### 3.3 GF(2) 方程视角

在不考虑具体 matrix 值的条件下，设未知量为 1288 位初始状态。每个观测到的 64 位 output_t 提供 64 个 GF(2) 方程。但乘法操作引入高次项（约 32 次），方程次数随步数增长：
- 步骤 t 的输出依赖于步骤 0..t-1 的 matrix 演化中累积的乘法操作
- 无已知低次逼近

## 4. 扩散分析

### 4.1 单步内扩散

```
raw[15:0] → matrix[row] → 影响指令字 → 影响下一步的 p, s0, s1, s2
```

raw 的低 16 位进入 matrix[row]，修改 row 的全部 16 位（XOR），再经 ROL16(p) 重排。p 从 0..15 均匀分布（矩阵随机假设下），平均扩散半径 7.5 位。

### 4.2 跨步扩散

16 步覆盖全部 16 行（idx 遍历 0..255，每 16 步 row 循环一遍）。任一行的修改通过以下路径影响后续步骤：

1. 修改的 matrix 位影响后续 curword → 影响 p, s0-s2
2. p 影响 row 内的位重排
3. s0-s2 影响选通 LFSR → 影响 raw → 影响后续回填

从单比特翻转到全矩阵影响的步数：初始修改 matrix[r] 的 1 位 → 当 idx 再次落到 row r 时（16 步后），该位的 p/sel 影响结果扩散到 matrix[r] 全部 16 位。约 3–5 个完整行遍历（48–80 步）实现全矩阵扩散。

## 5. 线性复杂度

- 单条 64 次本原 LFSR：线性复杂度 64
- 三路 XOR + 乘性混合：等效线性复杂度远超 2^64（乘性非线性）
- 矩阵反馈环（回填→读取→影响选通→影响回填）进一步加深非线性依赖

**保守估计**：输出序列的线性复杂度远超 2^20。实测 NIST 线性复杂度检验 100/100 通过，与 ChaCha20 无差异。

## 6. 已知攻击分析

### 6.1 相关攻击
- 三路 LFSR 选通 XOR 使单条 LFSR 的线性序列不可分离
- 64×64 乘性混合消除字内位关联（Golomb G3 0/32 PASS）
- s0/s1/s2 由 matrix 动态决定，攻击者无法将输出与固定 LFSR 关联

### 6.2 代数攻击
- 输出函数含乘法→高代数度
- 矩阵反馈使下一轮选通依赖乘性混合输出→高次方程组
- 1M 位密钥流对应 15625 步，需 ~10^6 个未知状态位，无已知低复杂度求解

### 6.3 区分攻击
- MF 设计：Monobit 100/100, Runs 100/100, 其余全部与 ChaCha20 同等
- Golomb G3 自相关 0/32 PASS
- 16 MiB 样本与 ChaCha20 不可区分

### 6.4 TMDTO
- 内部状态 1288 位，TMDTO 需要 2^644 预计算
- 有效密钥 256 位，最优攻击 = 2^256 穷举

### 6.5 滑动攻击
- idx 每步自增（无固定轮函数），状态不重复
- 矩阵行移位量 p 由状态决定，非固定参数

## 7. 退化状态分析

### 全零矩阵

```
matrix = [0, 0, ..., 0]
→ curword = 0 → p=0, s0=s1=s2=0
→ raw = (L_0 × K) → fill = 0xFFFF & raw → 取决于 L_0
→ row ^= fill → 破坏全零
```

全零矩阵**不自持**——第一步的回填就引入非零值。全零 LFSR 会自持（Fibonacci 反馈 = 0），但需同时 matrix 全零和 lfsr_seed 全零，且 matrix 回填无法消除 LFSR 零点。**init 时检查并拒绝 lfsr_seed 全零**即可。

### 重复行模式
16 行全相等 → 指令字固定 → s0/s1/s2 固定 → raw 固定 → 但 fill 逐行异或后各行的 ROL 量（p 全等）导致各行分化。约 2–4 轮行遍历后模式破裂。

## 8. 统计检验汇总

| 检验 | HLFSR-64 MF | ChaCha20 |
|------|------------|----------|
| Golomb G1 | 50.000% PASS | 50.004% PASS |
| Golomb G2 χ² | 2068 | 2072 |
| Golomb G3 | 0/32 PASS | 0/32 PASS |
| NIST Monobit | 100/100 | 100/100 |
| NIST Runs | 100/100 | 100/100 |
| NIST 矩阵秩 | 99/100 | 99/100 |
| NIST 线性复杂度 | 100/100 | 100/100 |
| 吞吐 | 238 MiB/s | 1760 MiB/s (SIMD) |

## 9. 安全性总结

| 属性 | 评估 |
|------|------|
| 等效密钥安全 | 256 位 |
| 内部状态 | 1288 位 |
| 线性复杂度 | 远超 2^20 |
| 代数度 | ≈ 32（乘性混合） |
| 周期 | ≥ 2^64−1 |
| 区分攻击 | 不可区分于 ChaCha20 (16 MiB) |
| 侧信道 | 常数时间缓解 |

**MF 设计优势**：
1. 纯代数结构——矩阵回填 + 行移位 + LFSR 选通，无复杂指令 ISA
2. 三路选通 XOR + 乘性混合提供非线性
3. 16 位回填 + ROL16 提供闭环自修改反馈
4. 统计质量与 ChaCha20 同等，吞吐 238 MiB/s

**已知局限**：
1. 缺乏形式化安全证明
2. init 时需检查 lfsr_seed 非全零
3. 尚未经公开独立密码分析
4. 无认证加密
